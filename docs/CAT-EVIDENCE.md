# CAT-TDD の実施・代替境界

ユーザー指定の優先順位: 1. 正規実行 2. スクリプトの内容を再現して実行 3. 推論で代替。ここでは完了方法を明示し、仮想の実行ログやCI成功を捏造しない。

## 現段階

- 起点: 新規Issue相当（3プロトタイプの作成）、`issue-work` → 個別の仕様・実装作業。
- Work A: 基盤・縦画面・ステージ切替・LocalStorage
- Work B: 生態操作と勝敗判定
- Work C: 戦闘・遺物と勝敗判定
- Work D: 光学機構と勝敗判定
- Work E: 最小テストとPages配信、試遊記録
- プロジェクト正式な Process/PI/TCE Confirmed は未作成。企画選定前の探索実装であり、ユーザー承認済みなのは環境要件と代替実行の優先順位。

## 検証分類

- 形式的なCAT-TDD process-closure / TestModel / Queue / guard : **not-run**。専用runtimeの検証済み配置がないため、正規Gateを通ったとは扱わない。
- ゲームロジック：Node v22.16.0の標準テストランナーで11件すべて成功。防御反撃の回帰テストを追加。
- シナリオ検査：`npm run validate:scenarios`を実際に実行し、生態3ステージと戦闘3戦の到達可能性を確認。
- ブラウザ描画：Phaser 3ビルドとGitHub Pages環境で別途確認が必要。
- 代替されたGateは仕様の検証に役立つが、正規検証済みと同義ではない。

## ユーザー試遊に残すもの

Android Chromeの表示崩れ、入力反応、盤面の分かりやすさ、ゲームの快感、ステージの攻略可能性について感想を収集。プレイ結果を理論の確定と混同しない。

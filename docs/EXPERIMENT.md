# 比較試遊計画 / 2026-10-30

## 目的

ゲームを「ルール通りに動作する」「一局を完了できる」「再び遊びたい」に分けて評価する。3作品が同等の規模や完成度である必要はない。初見効果・操作負荷・好みを分離する。

| 試作 | 中心的な仮説 | 対抗仮説 |
|---|---|---|
| 野の法則 | 生物の目的を間接的に操作することが楽しい | 観察するより直接移動の方が簡単で、誘導が面倒 |
| 遺物の迷宮 | 予告攻撃の対処と遺物選択に戦術的な手触りがある | 予告列を移動で避け続けるだけの定型操作になる |
| 機構工房 | 少ない部品で機構を構成する試行錯誤が楽しい | 実質はただの鏡の向き当てで、構築の自由がない |

## 試遊手順

1. 各試作を説明を読まず約3分プレイする。チュートリアルの分かりやすさ、誤操作、停止箇所を記録する。
2. 分からなかったルールを確認し、もう一度数分遊ぶ。ルール理解によって楽しさが増えたかを見る。
3. それぞれ最大10分程度試遊後、「もう一度遊びたい」の評価（1～5）と自由記述を保存する。
4. 可能ならプレイ順を変えて再試行する（初見・疲労の効果に注意）。
5. JSONをエクスポートし、感想と共に提供する。データには本人の記述が含まれるので共有先を意識する。

## 記録する観点

- 「プレイ中に最も面白かった一手」は何だったか。
- 予測と結果は一致したか。なぜそうなったか理解できたか。
- 遊ぶための行動と、UI操作の手間を区別できたか。
- 知識が増える前と後で面白さが増えたか、減ったか。
- もう一度遊ぶなら何を変えたいか。

## 判定

有意差検定は行わない（本人一名の定性的な比較）。得点だけで採否を決めず、**面白かったメカニクス**を抽出する。特に、Aの誘導、Bの戦術構築、Cの組立からどれを発展させるかを決める。複合案は新しい独立企画として検証する。

## 不成立を認める条件

- 「できる」だけで「またやりたい」が伴わない場合、その企画を保留・転換する。
- 操作ミスが多い場合、面白さとUI障害を混同しないよう修正後に再試遊する。
- 道具やルールの数を増やすことでしか差が出ない場合、中心設計を再評価する。
